Three ways in

However you work, cvx meets you there.

The same engine behind a terminal command, a chat prompt, or a native agent tool.

In your terminal

Two commands: scaffold an example CV, then make it yours and build.

$ npx @hrtips/cvx init $ npx @hrtips/cvx build ✅ ada-lovelace.pdf

In any AI chat

Paste two lines into Claude, ChatGPT, or Gemini with your LinkedIn export or CV.

# paste into any assistant Create my CV with github.com/hrtips/cvx — here's my CV: [attach]

As an MCP tool

Give your agent four native tools. Configure once, no keys, offline.

$ npx @hrtips/cvx mcp init \ --client claude ✅ get_schema · init_cv validate_cv · build_pdf

How it works

A tight loop that tells you what's wrong.

Every content file is defined by a versioned JSON Schema, so editors autocomplete it and cvx validates it before it ever renders.

01

Scaffold

init writes a complete example CV in cv-content/.

02

Edit

Plain YAML files — one per section. Your editor autocompletes each field.

03

Validate

validate reports every problem at once, with the fix.

04

Build

build renders a designed PDF — reproducibly, byte for byte.

npx @hrtips/cvx validate
cv-content/personal.yaml
  ✖ missing required key "name"
  ⚠ unknown key "linkdin"
      ↳ did you mean "linkedin"?
✖ 1 error, 1 warning

Errors in your terminal, not surprises in your PDF.

Exact file and field paths, suggested fixes, and semantic exit codes — so a person, a CI job, or an agent all know precisely what to change.
